# 2026-10-27 · 指纹去重 + 记忆曲线的账本

> 起因：上一个遗留问题——`我最近在忙什么` 在真库里有 3 条，库里只堆不清。

## 一、做了什么

**存储层加指纹去重哨兵**（`内核/存储适配器.js`）：

| 改动 | 位置 | 说明 |
|---|---|---|
| `内容指纹(角色, 正文)` | 新增 | sha1(角色\|归一化正文)，**刻意不含时间** |
| `取指纹索引(选项)` | 新增 | 内存账本 Map，以库文件 mtime 为准，外部改写自动重建 |
| `合并重复(选项, 指纹, 新句ID们, 时间戳)` | 新增 | 不新增行，只记一次「复习」 |
| `存入消息()` 前置判断 | 改 | 命中指纹 → 走合并，返回 `{ok:true, 跳过:true, 原因:'内容重复 → 已并入原条（第 N 次出现）'}` |
| `归一条目()` | 改 | 补 指纹 / 出现次数 / 首次时间 / 最近时间（不补则上层拿不到账本） |
| `入库一轮()` | 改 | 调用方向量层透传 `{根目录}`（原先没传，测试/多库场景会写错库） |

**为什么指纹里不装时间**：`造ID` 把时间算进了哈希，所以同一句话今天说明天说会变成两条新记忆。但对「记忆」这个概念来说，那不是两条，那是同一条被复习了两次。时间差不进指纹，进 `出现次数/首次时间/最近时间`——这三个量正是遗忘曲线的输入。

**去重不丢原文**：原文表（L1）照旧逐句追加，一个字不动。被并掉的条目的句ID全部收进 `句ID们`，所以三句原话仍然能逐句翻出来。验收第⑦条专门守这条红线。

**开关**：`选项.去重 = false` 可关（演练、造重复数据时用）。

## 五、遗留（明确不做，防过度施工）

1. **语义去重不做**：只有「同角色+逐字一致（空白归一）且」才并。意思相近但说法不同的两句（「我在忙啥」vs「我最近在忙什么」）不并——靠向量相似度并会把不同事实认成一条，误伤代价远大于收益。
2. **记忆曲线只落了账本，没落算法**：出现次数/首次/最近时间已经在库里，但没有强度衰减公式、没有按强度调度。检索的 `similarity` 仍是原始余弦（未叠时间衰减）。
