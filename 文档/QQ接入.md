# QQ 接入 · 从零到一只活着的鲸鱼

这份文档讲两件事：**怎么把机器人建出来拿到凭据（自动化），以及凭据到手之后怎么让它活起来。**

看完应该能自己跑通，不需要问任何人。

> ⚠️ **2026-11-02 真机更正（重要，推翻了本文旧版的立场）**
> 本文早先写的是「用户把 AppID/AppSecret 发给机器人作者，作者代他挂」。
> **这条路不存在。** 腾讯实测硬限制：
> `该机器人仅供创建人使用，暂不支持进入群聊`——一具机器人对一个人。
> 所以现在只有一种形态：**你自己就是作者，你建机器人、你把鲸鱼挂在自己名下。**
> 想给朋友用 → 朋友自己建一个。我们代不了，这是平台限制。
> 全流程不到 2 分钟，见 [`上手/陌生人安装清单.md`](../上手/陌生人安装清单.md)。

## 一、上手：两条路，先看你在哪一段

### 路线 A（推荐，什么都不用抄）：让安装器自己建

**适用于：你手上一个凭据都没有。**

```bash
node 适配器/qq/安装/一键装.js
```

它会：开一个**独立配置的浏览器窗口** → 判登录态 → **等你手机 QQ 扫码**（唯一需要人的一步）
→ 代点「创建机器人」→ 盯住创建成功那一屏把明文 `AppSecret` 拄走 → 写 `配置/qq.json` 并回读校验
→ 真调 `bots.qq.com` 验令牌 → 起常驻网关。

退出码语义（写 CI 时直接用）：`0` 全链通过 · `1` 崩了或浏览器/窗口/后台没起来 · **`3` 等扫码超时（默认 900 秒）** · `4` 代建没拿到凭据 · `5` 写配置/回读不符 · `6` 令牌验不通 · `7` 网关未 READY。

四份证据落在 `临时/一键装日志.json`：人动手次数、写配置回读、令牌、网关。

> **为什么必须代建而不是事后抄**：腾讯的 `AppSecret` **只在「创建成功那一屏」明文出现一次**，
> 一重渲染就永久掩码；而那个「查看」按钮**是重置入口，不可逆**。所以安装器写死三条禁令：
> 永不点「查看 AppSecret」· 永不删机器人 · 写配置前必定先备份。
> 抄丢了怎么办？**让安装器再建一个**，旧的删掉。别点查看。

### 路线 B：我手上已经有凭据

```bash
# 1. 填凭据（二选一，推荐环境变量）
cp 配置/qq.example.json 配置/qq.json     # 然后填 appId / appSecret
# 或
export QQ_BOT_APPID=你的AppID
export QQ_BOT_SECRET=你的AppSecret

# 2. 别急着上线，先验三层（凭据 → 令牌 → 网关）
npm run qq:dry

# 3. 真连，但先别真发消息（只入库，日志里能看到它准备说什么）
npm run qq -- --演练

# 4. 确认没问题，正式跑
npm run qq
```

`--dry` 只到 READY 就退，不碰任何数据。**这一步通过，说明凭据是真的、网关是通的、鉴权格式是对的**，后面每一步失败都不再可能是这三件事。
失败退出码 **1**，成功打印 `✅ dry 通过，退出码 0`。

## 二、凭据从哪来（路线 B 适用）

1. 打开 <https://q.qq.com>，用要挂机器人的那个 QQ 号登录（没号先注册）
2. 选机器人 → 开发 → **开发设置**，抄下 `AppID`（纯数字）和 `AppSecret`（若已掩码，见上游警告：不要点查看）
3. **沙箱环境**先跑通，再点「上线」
4. 群里用它：把机器人拉进群，群里 `@机器人 说话`

> 沙箱阶段只有开发者自己（以及加到沙箱白名单的号）能触发机器人。这不是 bug，是平台的灰度机制。
> 腾讯可能要求**实名认证**，这一步我们无法代做也无法预判——页面提示就按提示做。

## 三、三个必须提前知道的坑

### 坑一：旧文档的鉴权格式会让你撞 4004

网上大量教程（包括不少 2024/2025 的文章）写的是：

```
Authorization: Bot {appid}.{app_token}     ← 已废弃，照抄必报 4004 Authentication fail
```

现在正确的两种写法是：

```
WebSocket Identify : { "token": "QQBot {access_token}" }
HTTP 请求头         : Authorization: QQBot {access_token}
```

`access_token` 先用 `AppID + AppSecret` 去换：

```bash
curl -X POST https://bots.qq.com/app/getAppAccessToken \
  -H 'Content-Type: application/json' \
  -d '{"appId":"你的AppID","clientSecret":"你的AppSecret"}'
```

返回 `{"access_token":"...","expires_in":"7200"}`，有效期两小时。本适配器自动缓存、提前 60 秒刷新、并发合并成一次请求，用户不用管。

**这条错一次要查两小时，所以写在这里。**

### 坑二：被动回复只有 5 分钟窗口

群/单聊里，回复用户某条消息必须带那条消息的 `msg_id`，且**必须在 5 分钟内**。超时平台必拒，重试也白搭。

本适配器的处理：**本地就拦下来**，直接丢弃并记 `warn` 日志，不浪费一次请求。所以你会看到日志里偶尔有「被动回复已超 5 分钟窗口，丢弃不重试」——那不是故障，那是在省钱省时间。

同一条 `msg_id` 连发多条时，`msg_seq` 必须递增（1、2、3…），否则平台判重复、第二条静默失败。这一条也在适配器里替你做了。

### 坑三：主动推送有配额（这条影响的是产品语义，不是代码）

平台对「机器人主动开口」（用户没说，机器人自己说）有严格配额，而被动回复（用户先说话、机器人接话）不受这个限制。

> ⚠️ **数据待实测（2026-10-27 注）**：本文原写「约每群每月 4 条，一年 48 句」——这个数字**没有官方原文，也没做过真机实测**，是从社区二手资料搬来的。写此文时未存链接，属追责在臣的失误。
>
> 官方现行「发送消息」文档里能查到的只有：群主动推送 2026-06-22 全量开放且需群主打开【机器人主动在群聊内发言】；频控为 qpm 级（账号 30～60 qpm、单群 20 qpm）。旧版文档写明的是「频道每天每子频道 20 条」「私信每天每用户 2 条、每天累计 200 条」。社区里同一个限制还有「一天 4 条」的说法（相差 30 倍）。
>
> **结论**：方向性判断不变（主动开口有硬限、被动回复不受限），但**具体条数不得引用**，须后台额度页或真机灌测定数后再回填。

这意味着「她会忽然想起你」这种主动提话能力，在 QQ 上**不能按原样跑**。三种处理方式：

| 办法 | 效果 |
|---|---|
| **一天一句**（本项目的选择） | 超配额时平台直接拒绝，记日志，不重试。不封号、不扣分，只是那句没发出去 |
| 改成「下次用户说话时顺带提起」 | 完全绕开配额，产品语义略变 |
| 只在自己控制的场景主动说 | 例如每日定时一句早安，额度精打细算 |

**本项目的选择是第一种：一天一句，超了就超了。** 理由很简单——额度是平台的可变参数，随时可能变；而「她会记得你」应该体现在**被动回复时的原话准确度**上，那是我们的护城河，不靠平台施舍。

## 四、会话怎么分账本

内核只认一件事：**同一段对话要落在同一个会话名里**。名字定错了，原话就翻不出来。

| QQ 场景 | 事件 | 会话名 |
|---|---|---|
| 群里 @ 机器人 | `GROUP_AT_MESSAGE_CREATE` | `qq-群-{group_openid}` |
| 私聊机器人 | `C2C_MESSAGE_CREATE` | `qq-单聊-{user_openid}` |
| 频道 @ | `AT_MESSAGE_CREATE` | `qq-频道-{channel_id}` |
| 频道私信 | `DIRECT_MESSAGE_CREATE` | `qq-频道私信-{guild_id}` |

一个群一本账，一个人一本账。`入群/退群` 等系统事件**不入库**——那不是对话，混进来会污染检索。

群消息里的 `@机器人` 标记（形如 `<@!4014209280>`）会被剥掉再入库，否则你翻原话时满眼尖括号。只有图片/语音没有文字时，留个 `[image/png]` 占位——至少知道「他那天发了张图」。

## 五、回话用谁的模型（重要）

**用户自己填。** 理由：产品 MIT 开源、零成本，我们只管记忆，不碰算力。

**首选：填配置文件**（产品交付形态，改一个文件就行，不用碰环境变量）

```bash
cp 配置/llm.example.json 配置/llm.json   # 然后把 key 填进去
```

```json
{
  "地址": "https://api.deepseek.com/v1/chat/completions",
  "密钥": "sk-你的key",
  "模型": "deepseek-chat",
  "温度": 0.6,
  "超时毫秒": 30000
}
```

`配置/llm.json` 已在 `.gitignore` 里，**永远不进仓库**。

**环境变量只做临时覆盖**（优先级高于文件，调完就丢）：

```bash
export WHALE_LLM_URL=https://api.deepseek.com/v1/chat/completions
export WHALE_LLM_KEY=sk-你的key
export WHALE_LLM_MODEL=deepseek-chat
```

任何 OpenAI 兼容服务都行（DeepSeek / 通义 / 智谱 / Ollama 本地模型）。

**不填 key 也能跑**——自动降级成「只查记忆」模式：你问「我上次说过啥」，它把原话连同句ID念给你听，只是不会闲聊。功能降级，不崩。

启动时第一屏会直接报到钱从哪来，不用猜：

```
OK  模型 deepseek-chat · key sk-**** · 来源：配置文件 …\配置\llm.json
```

这正好也是产品的一条底线：**记忆是内核，模型是可换件。** 换模型不该影响「记得」这件事。

## 六、一条消息的完整命运

```
QQ 服务器推事件
   ↓
网关.js      WebSocket 收帧（心跳/重连/补漏都在这一层）
   ↓
归一.js      事件 → {会话, 角色, 文本, 时间}，剥@标记
   ↓
① 入库       ← 先写原文表，再写向量库。顺序反了，模型一挂这句话就永远查不回来
   ↓
② 检索       混合检索（字面 + 向量，RRF 融合）把相关原话找出来
   ↓
③ 生成       拼记忆上下文 → 调注入缝「生成回复」（默认 OpenAI 兼容，可替换）
   ↓
④ 回话入库   机器人自己说的话也进账本，否则下次它会自相矛盾
   ↓
⑤ 发送       带 msg_id 走被动窗口，msg_seq 递增
```

③ 那个「注入缝」是个普通函数：

```js
await 桥.处理事件('GROUP_AT_MESSAGE_CREATE', d, {
  生成回复: async ({ 消息, 记忆 }) => '你自己接任何模型，返回一段文本就行'
})
```

想接本地模型、想接别家的、想接规则应答，都只改这一个函数，内核一行不动。

### 「一轮」和「一段」：两个必须分清的事

- **一轮** = 同一会话内，用户最后一条到达之后静默满 2 秒的那几句话。
  「在吗」「我跟你说个事」「昨晚那个」是一轮，不是三件事。一轮只入库一次、只检索一次、只生成一次。
- **一段** = 鲸鱼对一轮的回复被切成的一条 QQ 消息。一轮回复 = 1–4 段。

上半段在 `攒话.js`（判定何时成一轮），下半段在 `切段.js`（怎么拆、拆几段）。
两半共用同一本额度账：平台被动回复只给 4 条，开「正在输入」要占掉 1 条。

拆的时候**换行和缩进走同一条数据通道**：每个块自带一个「前导」（来自上一行的就带 `\n`，行首空白原样保留）。段内前导照留，段首一律去掉前导。所以原文的两层列表切成段之后还是两层，不会被压平成同级列表。

只用一条也能跑：`桥.处理事件(...)` 就是「只有一句话的一轮」的薄包装，旧调用点一个不用改。

## 七、目录与职责

```
适配器/qq/
  凭据.js   找到、校验、脱敏。密钥绝不进日志/入库/提交
  令牌.js   换 access_token，内存+磁盘双缓存，提前 60 秒刷新，并发合并
  网关.js   WebSocket 长连接：Hello→心跳→Identify/Resume→退避重连→op9 重登
  归一.js   QQ 事件 → 内核认的 {角色, 文本, 时间}
  攒话.js   入向攒话桶：同会话最后一条静默满 2 秒 = 一轮（命令直放、重投丢弃、按会话分键）
  切段.js   出向切段：短的不拆，长的按 自然边界拆，总数不超平台额度
  队列.js   按会话分键的串行队列（A 会话生成中不阻塞 B；同会话仍严格串行）
  发送.js   发消息，超窗本地拦截，msg_seq 递增
  桥.js     把上面这些串成一条链，生成回复是注入缝
  主.js     入口：--dry / --once / --演练 / --回放

适配器/qq/安装/   ← 建机器人、拿凭据的全自动线（零依赖，只用 Node 标准库 + CDP）
  一键装.js  ⭐ 总入口：登录→建机器人→拿凭据→写配置→验令牌→起网关（人工只扫码一次）
  浏览器.js  把本机已有 Chromium 变成调试端点（不内置浏览器，不碰你日常配置）
  登录态.js  三条页面自身承认的事实判定登录态，不靠猜 cookie 名
  抄凭据.js  只读地拄 AppID/AppSecret（⛔ 永不点「查看」，那是重置入口）
  代建.js    代点「创建机器人」并盯明文（AppSecret 只明文一次）
  一步装.js  序③+④合并：扫码 → 拄凭据 → 落盘（一键装的下位，手动排错时用）
  装.js      第①步单独跑：只看登录态
```

**内核一行都没改。** 这是契约：调用方依赖内核，内核永不依赖调用方。想删掉 QQ 换 Discord，删掉 `适配器/qq/` 即可，内核照样跑五层验收。

## 八、验收：不连 QQ 也能跑

```bash
npm run qq:test
```

66 项断言，全程在系统临时目录、全程用假 WebSocket 和假 fetch，**不发一条真实请求、不写一个真实文件**。验的正是上面那几个坑：

- 鉴权格式必须是 `QQBot {token}`（防 4004 回归）
- 并发 4 次要令牌只发 1 次请求
- 超 5 分钟被动窗口本地就丢
- 同 msg_id 的 `msg_seq` 递增
- 生成器崩了，用户那句话照样入库
- 三句间隔 <2s 只调一次模型、入一轮三句；重投不重置计时
- 400 字含 4 换行切成 ≤3 段；某段 4xx 则后续段停发
- 两层缩进列表切完缩进逐字保留；段首不带空白；带缩进也不超单段字数
- 原文表必须落盘，且句ID 形如 `qq-群-G1#1.1`

跑完再看一眼总回归，确认没碰坏内核：

```bash
npm run selfcheck     # 十三层（L0–L11）
```

## 九、出问题了先看这几行

| 现象 | 大概率原因 |
|---|---|
| `--dry` 报 4004 / Authentication fail | 凭据错，或用了旧鉴权格式（见坑一） |
| 安装器报「找不到 Chromium 内核浏览器」 | 本机没 Edge/Chrome | 装 Edge（免费的，不内置是因为一个浏览器 ~150MB） |
| 扫码后窗口没跳转 | 网络断在 q.qq.com | 确认 <https://q.qq.com> 能打开 |
| 安装器反复报「未登录」 | 扫的是别的 QQ 号 | 用「要挂机器人的那个号」扫 |
| AppSecret 掩码了、怎么看都看不到 | 腾讯只在创建成功那一屏明文一次 | **别点「查看」（那是重置）**；让安装器再建一个，旧的删掉 |
| `--dry` 换令牌返回 401 | AppSecret 不对，或机器人被删了 |
| 连上了但群里 @ 没反应 | 机器人没上线 / 没拉进群 / 沙箱白名单没加你的号 |
| 日志刷「退避 Xs 后重连」 | 网络断了或令牌被别处换掉了，正常自愈，超过 5 次看网络 |
| 回复能发出但群里看不到 | 发送接口 4xx，看日志里的状态码，常见是被平台判重复（`msg_seq`）或超窗 |
| 它回答得很空、不像记得 | 检查 `数据/向量库.jsonl` 是否真的在长大；没配 embedding 会退回本地哈希向量，质量低但能用 |
