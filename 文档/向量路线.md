# 向量路线 · 鲸鱼的语义层怎么走

> 写于 2026-10-27。这份文档回答一个问题：**鲸鱼凭什么"记得意思"，以及它退化时退到哪一步。**
> 谁改动了向量层，请同时改这份文档。文档与代码不一致时，以这份文档为验收口径。

═══

## 一、一句话结论

鲸鱼默认带上 **40MB 的真语义模型**（bge-small-zh-v1.5，int8 量化，纯 WASM 推理），
开箱即有 512 维稠密向量，**无网络、无 API Key、无 Node 原生依赖**。
模型缺失或加载失败，自动落 bigram 哈希兜底（256 维），一条记忆不丢、一句不崩。

═══

## 二、为什么是"三级探测链"而不是"一个模型"

需求单硬约束：**主链路不得以某个 embedding 模型可用为前置条件。**
用户把 `模型/` 目录删了、磁盘只读、WASM 编译失败——鲸鱼不能因此不记事。

```
① 自定义 embed        调用方显式注入（用户自己的 API / 本地大模型）
    ↓ 不可用
② 随包小模型          bge-small-zh-v1.5 int8 / 512 维 / 纯 WASM（本档）
    ↓ 不可用
③ 哈希兜底            bigram 投影 256 维，零依赖，纯函数，永不失败
```

- 每一级都能独立出结果；任一级失败**静默落下一级**，但必须**说出来**：
  `向量后端.自动装配()` 的返回值里永远带 `降级[]` 与 `原因[]`。
- ③ 是链尾，也是"永远有结果"这句话的全部支撑。**任何改动都不许把 ③ 拿掉。**
- 装配只跑一次（进程内 Promise 单例），并发调用共享同一次加载，不会重复吃 40MB。

### 开关

| 方式 | 效果 |
|---|---|
| 默认 | 走完整链 |
| 环境变量 `鲸鱼向量=hash` | 跳过 ②，直接用 ③（省启动时间，验收对撞用） |
| 环境变量 `鲸鱼向量=off` | 同 hash，且语义上表示"永久关闭" |
| 调用参数 `自动向量:false` | 单次调用不触发装配（测试缝） |
| 调用参数 `向量模型:false` | 本次装配跳过 ② |

## 三、真实的体积账（不是 24MB）

模型权重只是其中一块，推理引擎另算。这是随包方案能不能成立的**全部成本**：

| 组件 | 内容 | 体积 |
|---|---|---|
| 模型权重 | `model_quantized.onnx`（int8，4 层 BERT，512 隐维） | 22.90 MB |
| 分词表 | `tokenizer.json` + config | 0.43 MB |
| 推理引擎 | `ort.min.js` + `ort-wasm-simd-threaded.mjs` | 2.6 MB |
| WASM 内核 | `ort-wasm-simd-threaded.wasm`（只留 CPU + SIMD） | 13.60 MB |
| **合计** | | **≈ 39.5 MB（实测 37.3 MB）** |

### 刻意没打进来的东西（每一条都是几十 MB）

| 排除项 | 体积 | 为什么不要 |
|---|---|---|
| `ort-wasm-simd-threaded.jsep.wasm` | 27.0 MB | GPU 用，鲸鱼纯 CPU |
| `ort-wasm-simd-threaded.asyncify.wasm` | 25.6 MB | 异步化变体，用不到 |
| `onnxruntime-node` | 287 MB | 多平台原生二进制，破掉"装哪都能跑" |
| `@huggingface/transformers` | ~9.5 MB + 上游依赖 | 它在 Node 下必然拉 onnxruntime-node |
| BGE-M3 | 2.2 GB | 用户可选下载，绝不随包 |

验收里 `一组_文件` 会逐条反查上面五项"未混入"，谁手滑 copy 进来当场红。

## 四、为什么不 require('onnxruntime-web')

npm 官方包装下来全平台 **138.7 MB**（四套 wasm 全带上）。我们只要 CPU 那一套。
所以运行集被裁进仓库：

```
第三方/onnxruntime-web/
  ort.min.js                      ← 加载器
  ort-wasm-simd-threaded.mjs      ← ESM 胶水
  ort-wasm-simd-threaded.wasm     ← 真正的推理内核
  LICENSE
```

`内核/向量小模型.js` 按**绝对路径**加载它，`wasmPaths` 传 `file://` URL（Node 下传裸路径会
`ERR_UNSUPPORTED_ESM_URL_SCHEME`，这个坑踩过，写在代码注释里了）。
用户想升版本，直接覆盖这三个文件即可，不用动代码。

## 四之二、装进宿主（ESM 包）时的三条硬约束

这一层是**唯一会因“换了个目录”而静默失效**的一层。实测踩过，记在这里：

### 约束一：第三方目录必须自带 `{"type":"commonjs"}`

`ort.min.js` 是 CJS 打包的。宿主插件（如 `whale-memory-dsh`）根 package.json 是 `"type":"module"`，
就近原则会把 `第三方/onnxruntime-web/*.js` 全当 ESM 解析 → 导出成空壳 →
`InferenceSession` 是 `undefined` → `Cannot read properties of undefined (reading 'create')`。

**报错信息里一个字都不提 type/ESM，文件也一个不缺。** 所以：

```bash
# 第三方/onnxruntime-web/package.json
{"type":"commonjs","private":true}
```

### 约束二：加载后立即验导出，不信任 require 成功

`require()` 不报错 ≠ 拿到东西。`向量小模型.js` 里：

```js
if (!ort || typeof ort.InferenceSession !== 'function') {
  const e = new Error('onnxruntime 运行集加载失败：InferenceSession 缺失。'
    + '多半是第三方目录缺 package.json（需 {"type":"commonjs"}），被上层 type:module 当 ESM 解析')
  e.code = 'ORT_BAD_EXPORT'
  throw e
}
```

### 约束三：自检必须真算一句话

`检查模型()` 只 `statSync` 查文件存在与大小。**文件全在而运行集是空壳时，它会报“✓ 就绪”。**
假绿比红贵——用户以为装上了真语义，用了半个月才发现拿到的是词袋。
所以 `适配器/dsh/装.cjs` 的自检用子进程真跑：

```js
// execFileSync(process.execPath, ['-e', 小脚本])
// 小脚本：创建嵌入器 → embed('自检') → 报 {维, 模长, 模型ID}
// 验：维度 === 512 且模长 ≈ 1
```

验收现场（Electron node 24.21，`ELECTRON_RUN_AS_NODE=1`）：
`后端=随包小模型，维度=512，降级=[]，猫/猫=1.0000，猫/天气=0.2270`

## 五、为什么不 require('transformers.js')

transformers.js 是这套方案的**起点**——第一版基线测试（`辅助工具/向量基线测试_L3.mjs`）
就是用它跑的，结论也确实好。但它进不了包：

- Node 环境下它 `import onnxruntime-node`，那是**多平台原生二进制 287MB**；
- 一旦带上，`装到任何机器都能跑` 这条需求单硬约束当场破掉。

所以改成自己写**两层薄胶水**：

1. **分词器**：`tokenizer.json` 驱动，实现 `BertNormalizer`（控字符清理 / 空白归一 / 中文逐字加空格）
   → `BertPreTokenizer`（标点独立）→ `WordPiece`（最长优先匹配 + `##` 续接 + `[UNK]` 兜底）。
   词表一个不写死，全从 tokenizer.json 读。验收 `二组_分词` 有 7 条断言钉住行为。
2. **前向**：`ort.Tensor('int64', BigInt64Array, [批, 长])` 喂 `input_ids / attention_mask / token_type_ids`，
   取 `last_hidden_state` 的第 0 个 token（`[CLS]`），L2 归一。

**池化口径必须是 CLS，不是 mean pooling。** bge 系列官方就是 CLS。换错池化，余弦分布会整体偏移，
门控阈值全部失效，而且症状很隐蔽（分数还是在 0.4–0.6 之间跳，看起来"像那么回事"）。

## 六、实测数字（同口径，可复验）

600 条对话记录 / 50 条查询，与上游 L3 基线完全同口径对撞：

| 档 | R@1 | R@5 | 来源 |
|---|---|---|---|
| TF-IDF 零依赖 | 28% | 48% | 参考基线 |
| BM25 关键词 | 46% | 64% | 参考基线 |
| **bge-small 单路** | **60%** | **72%** | 本文档（鲸鱼实测） |
| **bge-small + BM25 RRF** | 54% | **84%** | 本文档（鲸鱼实测） |
| BGE-M3 + BM25 RRF | 64% | 92% | 参考基线（2.2GB，不随包） |

两个要点：

1. **单路 60/72 打平参考基线（60/72）** —— 同一份权重，等价实现。
2. **「主动提一句」这个动作看 R@1。** 混合档 R@1 从 64% 掉到 54%，是 RRF 融合的固有代价
   （关键词路的强命中会挤掉向量路的头名）。所以**门控的 `cosine_literal` 走的是向量单路原始余弦，
   不是融合后的 rrf 分** —— 代码在 `候选映射.js`，别改成融合分。

命令：`node 验收/向量小模型验收.js`（约 13s，62 项断言）

## 七、门控阈值与标定的关系（改模型前必读）

`配置/门控策略.json` 的 `标定` 段声明了阈值的**适用范围**：

```json
"标定": { "模型": "bge-small-zh-v1.5", "维度": 512, "语料": "对话记录600条", "样本": 50, "状态": "experimental" }
```

`内核/门控策略.js:检查标定()` 会在每次判定时比对当前 embedding 的 **模型ID + 维度**：

- 一致 → 正常判定；
- 不一致 → **强制降 quiet + 告警**，绝不静默沿用旧阈值。

这条机制的代价是：**换成哈希兜底（模型ID=`bigram哈希256` / 256 维）时会静音。**
这是设计，不是 bug——256 维哈希余弦与 512 维真语义余弦不在同一个分布上，
沿用 0.65 的阈值等于拿错的尺子量。但**必须让人看见**：`当前嵌入元()` 会报
`模型ID / 维度 / 后端 / 降级[]`，装配日志也要有一条。

> 换 embedding 模型 = 阈值必须重标。步骤：改 `标定` 段的模型/维度 → 用真实语料重跑
> `门控策略验收.js` 的提出率/准确率 → 确认达标再把 `状态` 从 `experimental` 改掉。

## 八、库结构与迁移

每条记忆条目上挂着两个字段：`vector`（向量本体）、`模型ID`（谁算的）。

检索时**双重校验**：维度一致 **且** 模型ID 同源，才比稠密余弦。否则落稀分（bigram 稀疏余弦）。
这是为了防止两个模型（或两个维度）算出来的向量被拿去互相比余弦——那种相似度毫无意义，
但分数看起来很正常，属于最难查的一类错。

### 什么时候需要 `重算向量库()`

库里混着旧后端的向量（比如先跑了哈希 256 维，后来模型装上了）。老条目维度不符，
稠密分永远算不出来，只能靠稀分混——**能用，但是打折的**。

```js
const r = await require('./内核/向量后端.js').重算向量库({ 根目录 })
// → { ok, 总数, 重算, 跳过, 换维, 失败[], 模型ID, 维度 }
```

- 只重算维度/模型ID 不符的条目，其余原样跳过；
- 不动 `原文表`，不删任何字段，失败条目原样保留并列入 `失败[]`；
- 走 `embed批`，16 条一批，650 条约 12s。

## 九、验收口径（改一行就要重跑）

`node 验收/向量小模型验收.js` → 62 项，必须全绿。七组分别钉住：

| 组 | 钉什么 |
|---|---|
| 一、文件与体积 | 必需文件在位；权重≤26MB、引擎≤20MB、总量≤45MB；**五个该排除的大件必须不在** |
| 二、分词器 | 中文逐字、标点独立、英文不碎、512 截断、空串不崩、生僻字不抛错 |
| 三、向量本身 | 512 维、L2=1、同句幂等=1、改写>0.6、无关<0.4、批量=单条 |
| 四、降级链 | 缺模型/缺 wasm/开关关 → 落 256 维兜底**且入库检索照常**；恢复后重新装配回 512 维 |
| 五、离线 | 两个新内核文件**静态扫描无网络调用**；清空 API Key 后现场算出 512 维 |
| 六、检索质量 | 650 条出向量 ≤60s；单路 R@5≥70%、混合 R@5≥78%、混合>单路、单路 R@1≥55% |
| 七、端到端 | 真模型入库 4 条 → 4 条语义改写查询 top1 全中；**维度/模型ID 陷阱三条必须被拦下**；重算向量库真能迁移 |

## 十、已知边界（诚实清单）

1. **没有多线程。** `numThreads=1`。多线程 WASM 要起 worker（Node 下 `worker_threads` 与 ort
   的 worker 机制对不齐），实测收益小于复杂度。单条 10–20ms 已经够用。
2. **512 token 上限。** 超过就截断（取前 510 个 token + CLS/SEP）。长文档不要整篇丢进来，
   先切段再算。
3. **纯 CPU。** 没有 GPU/WebGPU 路径。要快就上 BGE-M3 + GPU，但那不随包。
4. **中文优先。** 分词器和模型都是中文调优的。英文短句可用（词表 21128 含常见英文 subword），
   但长英文文本效果不如中文。
5. **首次装配 300ms 左右。** 发生在首次入库时（不是进程启动时），并发调用共享同一次加载。
   这个延迟是刻意的：为一条空消息付 300ms 启动成本不值得，所以懒加载挂在"真的要算向量了"那一刻。
