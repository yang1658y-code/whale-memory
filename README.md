**它不只是记得你，它能把你当时那句原话翻出来给你看。**

## 这是什么

一只养在对话框里的鲸鱼，和一本能翻的回忆册。

绝大多数「记忆」方案的底层动作是**抽取 → 摘要 → 合并**：把你说过的话压成一句"用户喜欢简洁回答"。压完就没了——原话没了，轮次没了，上下文没了。用户问「我上次说那句话是什么来着」，它答不出来，只能再编一句。

这个项目多做一件事：**每一轮对话都双写**——一份进可检索的向量库，一份进**句级原文表**（`会话#轮次.句序`，只追加、不改写）。所以当它开口提起往事时，能连带把**哪一轮、第几句、前后说的是什么**一起拿出来。

## 四个能力

| 能力 | 做什么 | 落点 |
|---|---|---|
| **原文回溯** | 「先给这个事挂份需求单出来吧」→ 第 15 轮第 1 句 03:05，前后原文一并吐出 | `内核/原文回溯.js` |
| **真语义检索** | 512 维真向量，说「那只小动物」也能找到「我养了只猫叫豆豆」；模型随包，不联网不下模型 | `内核/向量小模型.js` |
| **双写账本** | 一轮对话两处落盘，向量条目挂句ID；原文表没写成，一条向量也不许写（不造孤儿条目） | `内核/对话入库.js` |
| **候选映射** | 检索结果 → 门控判得了的候选集，并挂上「这句能不能翻出原话」 | `内核/候选映射.js` |
| **主动提话** | 三档门控决定"该不该提"（安静/标准/活跃），阈值全部外置可标定；提完登记冷却，重启不忘 | `内核/门控策略.js` + `内核/提话冷却.js` |

## 快速开始

```js
const 存储 = require('./内核/存储适配器.js')
const 入库 = require('./内核/对话入库.js')

// 一轮对话入库：原文表 + 向量库，一次写两处
await 入库.入库一轮('我的会话', [
  { role: 'user', content: '先给这个事挂份需求单出来吧。' },
  { role: 'assistant', content: '需求单已立。' }
])

// 她记得什么
const 命中 = await 存储.搜索相关('挂个档案追踪一下', 5)

// 翻原话
const 原句 = require('./内核/原文回溯.js').找原句(命中[0].content, { topK: 1 })
console.log(原句.结果[0].句ID, 原句.结果[0].位置, 原句.结果[0].原文)
```

**环境要求**：Node.js ≥ 22。⚠️ 内核十层在 ≥18 上也能跑，但 QQ 网关与扫码浏览器用到内置 `fetch` / `WebSocket`（Node 22 才稳），在 18/20 上会一直绿到「扫码」那一步才崩——所以口径统一按 22 要求，省你一轮排查。**不需要 `npm install`**，运行时 npm 依赖 **0 个**。

零配置可跑，开箱就是**真语义**：随包带 `bge-small-zh-v1.5` int8 量化模型（23.3MB = onnx 22.90MB + tokenizer 0.44MB，
纯 WASM 推理，无网络、无 API Key、无原生依赖），512 维稠密向量。第一句话入库时就自动装好，不用你配任何东西。

```js
// 默认就这样，啥也不用写
const 命中 = await 存储.搜索相关('我家那只小动物叫什么名字', 5)  // → 命中「我养了一只猫，叫豆豆」
```

想换自己的模型（更准的、云端的）：

```js
存储.设embed(async (文本) => 你的模型.embed(文本), { 模型ID: '你的模型', 维度: 1024 })
```

**降级链恒成立**：自定义 → 随包小模型 → bigram 哈希兜底。任何一级不可用都静默落下一级，
不抛错、不丢记忆、检索照出结果。把 `模型/` 目录整个删掉，它退成关键词级，但一条记忆也不会少。
**主链路不以任何模型可用为前置。**

体积与三条路线（零依赖 / 随包 40MB / 可选 2.2GB）的完整账目见 `文档/向量路线.md`。

## 面板：拧得动的深度

```bash
npm run panel        # → http://127.0.0.1:9337
```

只绑 `127.0.0.1`，不上公网；`Ctrl+C` 关掉不留后台进程。零新依赖，一个 `node` 内置 `http` 就够。

四个页签：

- **总览**：记忆条数、原文句数、会话数、库体积、当前嵌入后端与生效档位——一眼看见它记得多少、现在怎么想。
- **翻原话**：输一句话，走真链路（过滤 → 两路召回 → RRF → 门控），直接列出命中的原话、时间、会话、交集数/余弦，以及**门控为什么开口或为什么不开口**（逐条 gate 说明）。
- **拧参数**：两档，一键切。
  - **通用版（默认・ 16 个旋钮）**：只摆拧错了顶多效果差一点的，全用人话命名——「它记得你们刚才聊了多少轮」「别把我的问句当记忆还给我」「一小时最多主动提几次」「想起旧事时，前后各带几句原话」。分六组：读多少轮上下文 / 多爱主动说话 / 想起旧话时带多少 / 翻得准不准 / 记什么 / 护栏（一般不用动）。滑块拖到底也不会炸；三个开关关掉后会当场跳黄字告诉你「关掉它会变成复读机」。
  - **专业版（45 个旋钮）**：三层渐进披露。外层三个开关（**记什么 / 多主动 / 多能翻**），中层按 L0–L8 分组（每个 L 号旁配一句人话，如「L4 候选映射 · 两路找法怎么对账」），里层全部 **34 条内核参数 + 11 条门控策略**。每条旁写着默认值、取值范围，以及**拧大拧小会怎样**——里面是实测数字（「调到 active 档，准确率从 96% 掉到 88%」），不是「建议值」。
  - 两档只是**显示范围**不同，写的是同一份配置：通用版改过的项在专业版里同样标黄。选过哪档记在 localStorage，也能用 `?模式=专业` 直拉。

  为什么默认只露 16 个：第一次打开面板的人应该只看到拧不坏的旋钮。会把提出率拧到 0、或让存量向量全废的选项，不在第一屏。哪些参数算「通用」不是前端白名单，而是 `内核/参数.js` 清单里的 `档` + `通俗名` + `通俗说明` 三个字段——**新加的参数默认落专业版**，想升通行版得同时写好人话。

  > **口径一致**：总览页的十三层清单、技术链路、`L0`–`L11` 编号在通用模式下全部不出现（只留人话），切到专业版才回来。一个词也不漏。
- **跑自检**：一个按钮跑 `npm run selfcheck`，十三层结果回终端，退出码摆在脸上。

**改完即生效，不用重启**：内核热读 `配置/内核参数.json` 与 `配置/门控策略.json`。改坏了直接把 `配置/内核参数.json` 的 `值` 段清空（或删文件），全部参数回出厂默认——默认就是最佳档。

> 哪些能拧、哪些不能，面板上写着呢：34 条参数里 32 条可调，2 条标「模型固有量」只读（向量维度、哈希兜底维度）——它们是骨骼，不是旋钮，改了存量向量全废。

**「先读多少轮上下文」是第一个旋钮（默认 8 轮）。** 模型回话前，先把最近 8 轮的逐字原文（你说的话 + 它自己说过的话）当聊天记录递过去——**换人说话才算一轮，你连着发好几条算同一轮**。这就是「刚才那个」「上次那事」接得住的原因；拧到 0 就只看当前这一句。更早的旧事不靠它，靠检索命中的原话（进 system 当资料，不冒充你发言）。

**L8 的两个旋钮也在面板上**：原先「一次最多带多少字」「每轮最多提一次」只是 `适配器/dsh/lib/记忆核心.js` 里的两个常量，想改只能动 `cordis.patch.yml`——而「翻到旧话时前后各带几句原文」更是只能改代码。现在三级优先级：`cordis.patch.yml` 里显式写了 → 听它（老配置一行不改仍生效）；没写 → 听面板；面板也没改 → 内置常量。热生效，不用重启。

## 结构：内核五层 + 适配三层

```
── 内核（内核/）—— 这五层不依赖任何适配器 ──────────────
L0 提话冷却     提完不忘，重启不重提（数据/提话冷却.json）
L1 原文回溯     句级账本，只追加不改写，索引可整表重建
L2 对话入库     双写 + 句ID 挂载，原文不成则向量不写
L3 向量层       随包 bge-small-zh-v1.5 int8 / 512 维 / 纯 WASM，三级降级链
L4 候选映射     检索结果 → 候选集，可回溯则挂原句
L5 门控策略     三档敏感度，阈值外置带标定标签（+ L5b 疑问句·空话·自引过滤）
   存储适配器   对存储的唯一入口（四方法契约）

── 适配（适配器/）—— 内核永不依赖它们 ─────────────────
L6 QQ 官方通道  适配器/qq/   凭据·令牌·网关·归一·发送·桥
L7 DSH 压缩接管 适配器/dsh/  接管压缩摘要，无模型也能压
L8 DSH 记忆注入 适配器/dsh/  把原话注入回对话，记得起
```

**内核五层可以在 `适配器/` 整个删掉的情况下各自独立跑通**——这是契约：调用方依赖内核，内核永不依赖调用方。
注意 `npm run selfcheck` 是**全量**体检：删掉 `适配器/` 后 L6–L8 会报「缺文件」，退出码 1。这是设计如此，不是坏。

## 验收

不靠肉眼，一键跑（Node ≥ 22，无需 npm install）：

```bash
npm run selfcheck        # node 验收/一键跑.js
npm run vector           # 只跑向量层（62 项，约 23s，含 R@5 对撑基线）
```

十三层断言全过才退出码 0。任一层断了就是那层的问题，不是环境的问题——每层都能在下一层不存在时独立跑通。

⚠️ **L3 的 R@5 那句要靠跨项目的基线语料**（约 650 条真实对话 + 50 条带金标的查询）。语料含真实对话、涉及隐私，**不进本仓**。所以：

- 干净 clone 里这六条会标「跳过」——条数照发、不算失败，断言总数不因环境而变（否则基线闸门又変成看环境吃饭的假绿）。
- 想在本机跑真测：仓根放个 `本地配置.json`（已 `gitignore`，不会进仓）写 `{"向量基线目录": "<那个目录>"}`，或设环境变量 `向量基线目录`。

同理 **L11（DSH 装机体检）会读宿主**：没装 DSH 的机器上全部标「跳过」算通过；装了则逐字节比 md5，并要求宿主里那几个契约点（`BasicCompactionEngine` 类、`summarize` 钩子、`compaction-basic` 节点、`agent/pre-step` 门）仍然在。

## 依赖与许可证

- 本项目 MIT。
- **运行期 npm 依赖：零个。** 随包小模型走裁剪后的 WASM 运行集（`第三方/onnxruntime-web/`，13.98MB，MIT），不走 npm 依赖树，不引入任何原生二进制。
- 随包模型 `bge-small-zh-v1.5`（int8，22.90MB）为 **MIT**，来源与升级步骤见 `模型/bge-small-zh-v1.5/来源与许可.md`。
- 不内置任何角色卡、不内置任何第三方逆向协议实现。QQ 通道走的是腾讯**官方**开放平台 API（`q.qq.com`），不是逆向协议。
- `适配器/qq/`（QQ 官方机器人与安装器）与 `适配器/dsh/` 在主仓内，但**内核永不依赖它们**：删掉 `适配器/` 后内核五层仍各自独立全绿。是否把它们拆去独立仓，尚未定。
