# whale-memory-dsh · 会记得你的鲸鱼 × DeepSeek Harness

**一句话：把 DSH 的「摘要式压缩」换成「归档 + 索引」，原话一个字都不交给模型改写；
再把手里记得的原话，在模型真正读到时递到它眼前。**

## 装一下（最快路径）

```bash
# 0. 前提：DSH 桌面端至少启动过一次（不然没有 ~/.dsh/profiles/<名字>）
cd 适配器/dsh

# 1. 预检（只读，一个文件都不改）
node 装.cjs

# 2. 装：复制插件 + 登记 dependencies/bundles，profile/package.json 先备份
node 装.cjs --装
#    只找到一个 profile 就直接用；有多个会列出来，用 --profile=<名字> 指定
#    （也认环境变量 DSH_PROFILE）

# 3. 手动重启 DSH 桌面端（本插件不替你重启任何东西）

# 4. 日志里出现下面这行 = 成了
#    whale-memory: 记忆注入已挂载（内核检索层可用）
```

**你的记忆存在 `~/.dsh/whale-memory/原文回溯/`——不在 `node_modules` 里。**
插件怎么升级、重装、删掉重装，都不动它。第一次装时若发现旧位置有原文表，会自动复制一份过来（源目录不删）。

卸载（DSH 立刻回到官方摘要，这是拆除接管后的应有行为）：

```bash
node 装.cjs --卸
```

## 配置（英文键 / 中文键都认）

写在 DSH profile 的 `cordis.yml` 里本包节点下，或直接用本包自带的 `cordis.patch.yml` 默认值：

| 英文键（推荐） | 中文键（兼容） | 默认 | 作用 |
|---|---|---|---|
| `enabled` | `启用` | `true` | 总开关，关掉后一步都不碰 |
| `everyTurn` | `每轮一次` | `true` | 只在本步有新用户输入时检索（省 token、保 KV 前缀） |
| `maxInjectChars` | `最大注入字符` | `900` | 注入文本硬上限（字符） |
| `contextPairs` | `上下句数` | `1` | 翻原话时带上前后各几句 |

英文优先、中文兼顾：老配置一行不改，升级后行为不变。

## 定位（三句话，先说清边界）

1. 本插件只管「本进程里握有对话循环的一方怎么压缩、怎么提话」。
2. QQ 链路**不经过 DSH**，与本插件无关；本插件只在 DSH 进程内生效。
3. 若换成自写前端 + 自定义 driver，本插件里面的内核逻辑照样可用，只需卸掉它的 DSH 外壳。

本插件现分两半边：

| 半边 | 入口 | 管什么 |
|---|---|---|
| 压缩 | `index.js` | **历史怎么退场**：遮蔽时把原话逐字归档，原位置只留一张索引卡 |
| 记忆 | `记忆.js`（`whale-memory-dsh/memory`） | **历史怎么上场**：本批入库 + 检索旧库，命中则在 `agent/pre-step` 追加一条原话消息 |

两半边共用同一套内核与同一张原文表（根目录由 `lib/路径.js` 一处算，归档写这里、检索读这里）。

## 一、要解决的问题

DSH 的官方压缩后端（`@deepseek-ai/dsh-compaction-basic`）做的事是：

> 会话变长 → 取一段老历史 → **让模型把这段历史用自己的话重写一遍** → 用这段重写替换掉原始消息。

重写的那一刻，原话就永久没了。之后模型记得什么，全看它当时改写得好不好。
这不是"压缩"，这是**有损转录**。

本插件做的事：

> 会话变长 → 取一段老历史 → **逐字写进本地原文表（不经过任何模型）** →
> 在原位置留一张「归档索引卡」（句数、字数、句ID 区间、机械关键词、怎么取回）

模型看到的不再是「别人转述的你」，而是「一张目录卡」；需要细节时按句ID/关键词回原文表逐字翻。

## 二、凭什么能接管（不是猜的，是从 asar 里挖出来的）

| 事实 | 出处 |
|---|---|
| 官方压缩契约是三个操作：`compactIfNeeded` / `compactNow` / `compactRegion` | `@deepseek-ai/dsh-compaction/lib/index.js` |
| `BasicCompactionEngine` 里**唯一的子类定制点**是 `summarize()` | 源码注释原文：`"summarize() is the sole subclass customization hook"` |
| 而且它是**动态派发**的 | `regionDependencies()` → `summarize: (input, owner, abort) => this.summarize(input, owner, abort)` |
| 官方有一条断言：替换消息必须比被遮蔽内容**小** | `"summary is not smaller than the shadowed content"` |
| 插件能 import 宿主包 | `dsh-app-boot` 的 `collectInstallationScopePackages()` 把 app 的 `dependencies + peerDependencies` 整个 installation scope 提供给每个 profile 的插件 |

所以本插件的全部做法就是：**继承官方引擎，只覆盖 `summarize()`**。

- 锁（`compaction/start`–`compaction/end`）、表层替换（`surfaceOp: replace`）、
  token 计价、tool-pairing 平衡 —— 全部仍走官方实现（这些的正确性不该由我们重写）
- 只有「那条替换消息里写什么」换成我们的索引
- 官方那条 LLM 摘要路径（`summarizeWithLlm`）**在这个类里一次都不会被调用**

## 三、三重保险（任一失效都不会退回官方摘要）

| # | 保险 | 失效时的表现 |
|---|---|---|
| 1 | `cordis.patch.yml` 把 `compaction-basic` 插件节点 `disabled: true` | 官方摘要后端根本不加载 |
| 2 | 我们的引擎覆盖 `summarize()`，从不调父类实现 | 即使 basic 被当库加载，摘要路径也走不到 |
| 3 | 引擎**永不抛错**（归档失败就降级成一句「归档失败」，照样返回索引） | 不会因为异常回落到官方路径 |

唯一的例外是应急阀：`鲸鱼关闭接管=1` 时**故意**走官方摘要（只在排查官方 bug 时用）。

## 四、装 / 卸 / 验

```bash
# 预检（只读，什么都不改）
node 适配器/dsh/装.cjs

# 装进 DSH 桌面 profile（会先备份 profile/package.json）
node 适配器/dsh/装.cjs --装
#   → 然后**手动重启 DSH 桌面端**（本项目铁律：不许任何程序替你重启）

# 卸掉（恢复原状，DSH 会回到官方摘要——这是拆掉接管后的应有行为）
node 适配器/dsh/装.cjs --卸

# 验收（离线，不依赖 DSH 运行时，11 项）
node 验收/压缩接管验收.js
node 验收/一键跑.js        # L7 已并入
```

装机做了六处改动（profile/package.json 有 `.bak.鲸鱼装前` 备份）：

1. 插件目录复制到 `<profile>/node_modules/whale-memory-dsh`
2. `profile/package.json`：`dependencies` 加本包，`dsh.profile.bundles` **末尾追加**本包
   —— bundles 顺序决定 patch 叠加顺序，必须在 `@deepseek-ai/dsh-base` 之后才能禁用它的节点
3. **内核标 CJS**：往包内核目录写 `内核/package.json` = `{"type":"commonjs"}`。
   不写这个，内核在本包（`type:module`）里会被当 ESM，`require()` 直接抛 ERR_REQUIRE_ESM，
   表现为「内核不可用 → 静默降级成兜底」——不报错，但再也不写内核原文表
4. **带门控配置**：`配置/门控策略.json` 复制进包。缺了内核会静默回落成「quiet + 全疑问句」
5. **内核数据接出包外**：包内的 `数据/` 建成 **junction** 指到 `~/.dsh/whale-memory/内核数据`
   （向量库 / 提话冷却就在那儿）。内核代码一行不改，但数据不住 node_modules 里
6. **原文表搬家**：旧位置有原文表就复制到 `~/.dsh/whale-memory/原文回溯/`（只复制不删源）

重跑 `node 装.cjs --装` 是幂等的：包被整个重铺，数据位置与数据本身不变。
**npm 重装/升级本包后，请重跑一次装脚本**（重铺包目录会重建内核、配置与 junction）。

profile 自动发现：扫 `~/.dsh/profiles/*/package.json`；只有一个直接用它，多个就列出来让你 `--profile=<名字>` 指定，**绝不默默猜一个**。

## 五、开关与降级

| 环境变量 | 作用 | 默认 |
|---|---|---|
| `鲸鱼原文表` | 原文表根目录（验收/演练用，优先级最高） | — |
| `原文回溯根目录` | 同上（内核自己认的键，优先级次之） | — |
| `鲸鱼数据目录` | 老版本遗留键，其下拼 `原文回溯/` | — |
| `鲸鱼内核` | 内核 `原文回溯.js` 路径 | 自动探测（项目内 / 插件内） |
| `鲸鱼检索` | 内核 `候选映射.js` 路径 | 自动探测（内核同目录） |
| `鲸鱼入库` | 内核 `对话入库.js` 路径 | 自动探测（内核同目录） |
| `鲸鱼禁用内核` | `1` = 强制走自带兜底写入（断内核演练用） | 关 |
| `鲸鱼索引上限` | 索引字符硬上限 | `1200` |
| `鲸鱼关闭接管` | `1` = 退回官方摘要（应急阀） | 关 |

**原文表默认落点：`~/.dsh/whale-memory/原文回溯/`**（优先级从高到低：
`鲸鱼原文表` → `原文回溯根目录` → `鲸鱼数据目录/原文回溯` → `~/.dsh/whale-memory/原文回溯` → 包目录兜底）。

为什么不用包目录：包目录里的东西 `npm update` 一次就没了。记忆不能住在随时会被清空的房间里。

降级原则：**少一块功能，不许整个插件崩。**

- 内核不在 → 自带同格式兜底落盘，句ID 标 `会话#0.N`，照样能查
- 写入失败 → 索引里明写「归档失败：<原因>」——**降级实况，不假装记得**
- 同一段历史被重复送进来（overflow 重试会这样） → 指纹命中，不重复追加
- 极小段落（几十字） → 索引自动缩短，**绝不撞**官方「必须比原文小」那道断言

## 六、模型看到的替换文本长什么样

小段（103 字）：

```
〔历史归档·原话未丢〕4 句 / 103 字已移出上下文，原话逐字存于原文表（样例小#1.1 ~ 样例小#1.5），未做任何摘要。
· 已归档 4 句（内核写入）
```

大段（1910 字）：

```
〔历史归档·原话未丢〕本段更早的对话已移出上下文，原话逐字存于本地原文表，**未做任何摘要改写**（不是压缩摘要，是索引）。
· 规模：40 句 / 1910 字
· 句ID 区间：样例大#1.1 ~ 样例大#1.40
· 会话：样例大
· 高频词（机械统计，非摘要）：策略、窗口、候选、记清、检索、接管、门控、清楚、取舍
· 取回：按句ID 或关键词查本地原文表即可逐字翻出，不依赖本段上下文。
· 已归档 40 句（内核写入）
```

注意「高频词」是**双字组频次统计**，不是模型理解出来的主题——刻意不让任何模型参与。

## 七、已知限制（诚实清单）

1. **还没在真实 DSH 里跑过端到端。** 11 项验收全部离线，验的是「引擎逻辑 + 包形态 + patch 硬开关」，
   没有验「DSH 是否真的加载了它」。这一步必须装上去、重启、实际让会话长到触发压缩才算数。
2. **模型不能主动取回原话。** 目前索引只是告诉模型「原话在哪儿、怎么取」，
   还没有注册 model-facing tool（`回忆(句ID)`）。这是下一步，不是已完成项。
3. **关键词有噪音。** 纯双字组统计会出现「控策」「量检」这类跨词碎片，已用虚词规则过滤一部分，未做词典分词。
4. **极小段落（< 40 字）的索引退化成一句话。** 那种段本就不该被压缩，索引只保证「小于原文、不撞断言」。
5. **DSH 是 `rc` 版本。** `peerDependencies` 一律写 `*`。上游改了 `summarize` 签名或 `regionDependencies` 的动态派发，
   本插件会失效——失效表现是「退回官方摘要」而不是「崩溃」，但这仍然是失效。
6. **拆掉即恢复官方摘要。** 卸载后 DSH 回到它自己的行为，这不是 bug。
