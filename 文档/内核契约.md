# 内核契约

这份文档只讲一件事：**谁可以依赖谁，以及边界在哪。**

对外发布的开源项目，最怕的不是功能少，是拆不掉。拆不掉的原因通常只有两个：代码里埋了别人的路径，或者数据里混了别人的内容。这份契约就是为了堵这两个洞。

---

## 一、依赖方向（单向，不可逆）

```
调用方（你的鲸鱼 / 你的 bot / 你的网站）
        │
        ▼
   会记得你的鲸鱼（本仓库）
        │
        ▼
   存储适配器.js  ←── 唯一出口
```

**规则：本仓库永不 require 仓库外的任何业务代码。**

本仓库内可以 require 的，只有本仓库的文件与 Node 标准库。不许出现 `../宿主项目` 一类的路径，也不许 require 某个 host 项目的内部模块。

反过来，**调用方可以注入实现**：

```js
存储.设embed(async (文本) => 外部模型.embed(文本))
```

或者把整个存储层换掉：

```js
await 入库.入库一轮(会话, 消息们, { 向量模块: 你自己的存储实现 })
```

只要你的实现满足下面四方法，内核一行都不用改。这是「项目永不引上游、上游可以引项目」的落地方式——单向依赖 + 注入缝，不是双向耦合。

---

## 二、存储适配器四方法契约

| 方法 | 签名 | 必须做到 |
|---|---|---|
| **存入消息** | `(角色, 正文, 时间, _, 新鲜度档, 来源, 权威性, 附加) → {ok, id?, 跳过?, 原因?}` | 不抛错；写不进去也要返回 `ok:false` 并说原因。空正文/过短 → `{ok:true, 跳过:true}` |
| **搜索相关** | `(查询, topK, 来源) → [{content, similarity, ...}]` | 按相似度降序；`similarity` 是原始相似度，**不叠时间衰减/权威加权**（门控阈值就靠这个原值标定） |
| **写入向量库** | `(条目们) → {ok, 写入}` | 整表覆写。用于存量补挂句ID 这类批量改字段 |
| **读原文** | `(会话, 选项) → {句: [...]}` | 转发 L1 原文表。**原文账本只有一个**，适配层不许自建第二份 |

兼容方法（L4/L5 会顺手调，缺了要能降级）：`读取向量库()` / `关键词检索(查询, topK)` / `搜索相关混合(查询, topK, 来源)`。

### 附加字段白名单

`附加` 只允许这几项进库：`句ID` / `句ID们` / `会话` / `轮次` / `段ID` / `轮` / `标签`。

别的字段一律不落盘——防止调用方顺手塞进整段上下文，把库撑爆，也防止将来换实现时字段含义漂移。

---

## 三、句ID：唯一的溯源坐标

格式：`会话#轮次.句序`，例：`会话A-2026-10-26#15.1`。

- 向量条目上的 `句ID` / `句ID们` 是**指针**，不是副本。
- 指向的原文表只追加不改写；索引可以整表删掉重建，原文表永远不重算。
- 换 embedding 模型只重建向量，原文表一条不动——这是「原文不可丢原则」的实现方式。

---

## 四、断依赖演练（架构错了跑不过）

把下面任何一项拿掉，产品必须**降级但不崩**：

| 拿掉什么 | 期望行为 |
|---|---|
| 数据目录（原文表/向量库） | 记忆功能停摆，对话照常；只记 warn |
| 外部 embedding | 自动退回本地哈希向量；检索质量降，功能不降 |
| 配置文件 | 按代码内最保守默认跑（安静档 + 全疑问句），只记 warn |
| 整个前端/外壳 | 内核仍可用 CLI 驱动全链路 |

验收方式：

```bash
node 验收/一键跑.js
```

任何一层断了就是那层的问题，不是环境的问题——每层都能在下一层不存在时独立跑通。
